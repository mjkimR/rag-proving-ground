# ADR-0003: 고속 텍스트 추출 우선을 위한 pymupdf4llm 기반 경량 파서 도입

* **작성일 (Date)**: 2026-06-11

## 맥락 (Context)
- Baseline 파서인 Docling은 테이블 및 레이아웃 복원 정밀도가 우수하나, CPU/GPU 부하가 크고 처리 지연 시간(Latency)이 긺.
- 도표나 특이 레이아웃이 없는 단순 텍스트 중심 문서(규정집, 매뉴얼, 일반 보고서 등)를 대량 처리할 때 Docling 단독 사용은 인프라 비용 대비 효과(ROI)가 매우 낮음.
- 따라서 속도 중심의 고속 경량 파이프라인 개발 요구 발생.
- 단, 원시 PyMuPDF(fitz) 단독 사용 시 원본 레이아웃의 의미론적 구조(대제목, 표, 단락 구분) 복원을 개발자가 직접 좌표 기반으로 구현해야 하여 개발 공수가 매우 큼.

## 결정 (Decision)
> **요약**: 고속 경량 파서의 하부 라이브러리로 **`pymupdf4llm`을 도입**하고, `PDF → Markdown 변환 → 마크다운 AST 파싱 → ParsedDocument IR 구축` 파이프라인을 구축하기로 결정함.

- 사용자가 실험 목적이나 리소스 상황에 맞춰 **정밀 구조 파싱(Docling)**과 **고속 텍스트 파싱(pymupdf4llm)** 중 플러그인 형태로 파서를 선택할 수 있도록 설계함.

## 근거 (Rationale)
1. **바퀴의 재발명 방지 및 개발 생산성**:
   - `pymupdf4llm`은 PyMuPDF 개발사(Artifex)에서 제공하는 공식 확장 도구로, 폰트 크기, 스타일, 레이아웃을 자체 연산하여 준수한 품질의 마크다운(Markdown) 형태로 1차 복원해 줌.
   - 로우레벨 좌표 데이터를 직접 파싱하는 오버엔지니어링 코드를 배제하고, 마크다운 변환 결과물을 AST 파서로 분석하기만 하면 되어 구조화 작업이 단순해짐.
2. **속도 및 리소스 최적화**:
   - C 라이브러리 기반의 무겁지 않은 연산으로 구동되어, CPU 전용 저사양 환경에서도 Docling 대비 10배~100배 이상의 고속 텍스트 추출 성능 제공.
3. **다단 레이아웃 및 간이 표 처리**:
   - 단순히 위에서 아래로 긁어오는 방식과 달리 다단 문서의 독해 순서(Reading Order) 정렬 및 마크다운 표(`|---|`) 복원 기능을 자체 제공함.

## 결과 (Consequences)
* **긍정적 효과**:
  - 단순 문서의 대량 인제스션 처리 시간 및 클라우드 GPU/CPU 서빙 비용 대폭 절감.
  - 파서 어댑터 인터페이스 레이어에 연동하여 비동기 워커가 필요에 따라 파서 엔진을 런타임에 동적으로 변경 가동할 수 있음.
* **부정적 효과 및 완화 조치**:
  - 복잡한 이미지 중심 보고서, 차트, 손글씨 스캔 문서 등의 레이아웃 정밀 추출 품질은 Docling 대비 열세함.
  - **완화 조치**: 문서를 업로드하는 API 또는 Knowledge Base 설정에서 파서 옵션을 선택할 수 있게 하고, 복잡한 비주얼 문서인 경우 Docling을 기본으로 사용하도록 가이드함.
